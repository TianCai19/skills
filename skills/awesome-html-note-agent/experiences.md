# 可复用修改经验

## 交互式 HTML 笔记页迭代经验

1. **先用 Playwright 做真实页面巡检**：不要只看代码，应检查桌面端、移动端、横向溢出、正文宽度、控制台报错和关键交互是否可用。
2. **三栏布局要优先保证正文阅读区**：目录和工具栏不能过宽，桌面端正文建议保持约 760–860px，避免中间笔记区域被挤压。
3. **内容不能只停留在概念摘要**：技术笔记应补充公式推导、数值例子、结构图、复杂度解释和参考资料来源。
4. **可视化要服务理解**：用 SVG/热力图/流程图展示 Q/K/V、Attention 矩阵、Mask、多头结构，比纯文字更容易建立心智模型。
5. **交互元素要有学习反馈**：滑块、动态权重、实时 softmax 结果等交互应能让用户“动手改变参数并看到结果”。
6. **移动端导航需要折叠**：长文的 TOC 在移动端应默认收起，提供展开/收起，并在点击目录后自动收起。
7. **代码块移动端要避免横向滚动失控**：可通过更小字号、自动换行、复制提示或展开按钮改善阅读体验。
8. **每轮修改后都要复测**：尤其是新增可视化和交互后，需要确认无 JS 报错、无横向溢出、TOC 数量正常、交互状态正确。

## 推荐工作流

1. 收集用户反馈与页面问题。
2. 用 Playwright 量化问题：截图、宽度、溢出、控制台、交互结果。
3. 针对问题修改页面结构、样式、内容和脚本。
4. 再次用 Playwright 验证。
5. 询问用户是否满意；满意后将可复用经验沉淀到 `experiences.md`。
